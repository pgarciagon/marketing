# Channels

Channel documents describe how an approved message should be adapted and verified on a specific destination. They do not contain credentials.

## Channel categories

| Category | Examples | Main concern |
| --- | --- | --- |
| Owned | `koinos.io`, documentation, Medium, official social accounts | Authority, consistency, accessibility, and durable links |
| Community | Telegram, Discord, forums, CMC Community | Context, dialogue, moderation, and avoiding repetition |
| Earned | Journalists, podcasts, newsletters, research outlets | Newsworthiness, evidence, independence, and disclosure |
| Data platforms | CoinMarketCap, CoinGecko, explorers, directories | Exact identifiers, current metadata, and official request procedures |
| Developer | GitHub, technical forums, package ecosystems | Reproducibility, versioning, and maintainer context |

## Channel guide template

For each channel, document:

- purpose and primary audience;
- official destination URL;
- account or publication authority by role, not secrets;
- supported formats and practical limits;
- review and approval expectations;
- link, image, and accessibility requirements;
- platform-specific risks;
- post-publication verification steps;
- metrics that inform a real decision.

## Common adaptation rules

- The source message remains factual across channels; length and framing may change.
- A Telegram reply needs conversation context. A press pitch needs independent relevance. A technical post needs reproducible evidence.
- Do not paste identical engagement prompts across many accounts or communities.
- Check the destination’s current rules before a campaign begins.
- Store no login details, session data, private messages, or API credentials here.
