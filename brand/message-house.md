# Koinos external message house

- **Status:** working baseline
- **Audience:** contributors communicating with people outside the existing Koinos community
- **Last verified against official website and documentation:** 2026-09-13

This message house keeps the public narrative recognizable while allowing each campaign to focus on a specific audience and proof point. It is not permission to repeat every statement in every post.

## Core identity

### Primary line

**Web3 for Everyone**

### Supporting line

**Feeless, Frictionless, Familiar**

### Plain-language description

Koinos is a general-purpose blockchain designed to let developers build applications with a familiar user experience. Its mana system allows applications to use blockchain resources without requiring every user action to spend a transaction fee.

## Narrative

Web3 will not reach ordinary users by asking them to understand infrastructure before receiving value. Koinos approaches the problem from the application experience: accounts and smart-contract interactions can be designed so that a user does not need to acquire tokens simply to begin. Underneath that experience is an open-source, modular blockchain whose protocol can evolve through on-chain governance.

## Message pillars

### 1. Familiar application experiences

**Claim:** Koinos is designed to help applications offer an experience closer to familiar web products.

**Explain it with:** Mana is a rechargeable network resource. It can be delegated, allowing an application or another account to cover resource use for a user.

**Evidence to use:** Current official documentation, a functioning application flow, or a reproducible transaction example.

### 2. Developer flexibility

**Claim:** Koinos uses WebAssembly, protocol buffers, and a microservice architecture to support a flexible development environment.

**Explain it with:** Developers can work with supported SDKs and standard interfaces instead of learning a chain-specific virtual machine language for every task.

**Evidence to use:** The current [Developer Hub](https://docs.koinos.io/), maintained SDK repositories, and released examples.

### 3. An evolving protocol

**Claim:** Koinos was designed so core protocol behavior can be upgraded through governance rather than requiring every change to become a conventional chain fork.

**Explain it with:** Important system behavior is implemented in upgradeable smart contracts, while governance determines which changes become active.

**Evidence to use:** Approved proposals, on-chain records, current system-contract documentation, and concrete upgrade histories.

### 4. Open participation and lived history

**Claim:** Koinos is open source and has been shaped by developers, operators, application builders, and community members across multiple phases of the network.

**Explain it with:** Use named, verifiable examples from the documentary chronology without turning activity counts into a hierarchy of importance.

**Evidence to use:** Repositories, releases, applications, public proposals, attributable articles, and the maintained Koinos chronology.

### 5. Fair-launch roots

**Claim:** The initial KOIN supply was distributed through a public proof-of-work mining period on Ethereum rather than a conventional token sale with private allocations.

**Explain it with:** Describe the historical mechanism and dates; do not use it to imply that ownership is currently evenly distributed.

**Evidence to use:** The official whitepaper, mining contracts, historical records, and the documentary chronology.

## Voice and tone

Koinos communication should be:

- **Clear:** explain the mechanism rather than relying on slogans.
- **Confident but bounded:** state what is shipped and distinguish it from goals or proposals.
- **Technically credible:** link to evidence and acknowledge meaningful limitations.
- **Human:** connect infrastructure to the user or builder problem it solves.
- **Community-aware:** credit specific work without pretending the ecosystem is one organization.
- **Accessible:** define terms such as mana, VHP, proof of burn, and forkless upgradeability when needed.

## Terminology

| Prefer | Clarify or avoid |
| --- | --- |
| `Koinos` for the network | Do not use `KOIN` as if it means the entire ecosystem |
| `KOIN` for the native coin | Distinguish it from wrapped KOIN representations |
| `feeless transactions` with an explanation of mana | Avoid saying network resources have no cost or limit |
| `designed for forkless upgrades` | Avoid claiming that forks are impossible |
| `community-governed` when current evidence supports the context | Do not imply that every community member approved a statement |
| `proposal`, `prototype`, `testnet`, or `released` precisely | Do not describe roadmap work as shipped |

## Claims that require fresh verification

- Price, volume, liquidity, supply, exchange availability, and market rank.
- Contract addresses and bridge support.
- Current roadmap dates and release status.
- Team, foundation, maintainer, or spokesperson roles.
- User, account, transaction, node, or application counts.
- Security, performance, throughput, and decentralization comparisons.
- Legal, regulatory, partnership, or funding status.

## Claims to avoid

- Guaranteed returns, price outcomes, or investment safety.
- “Free” without explaining resource limits and who supplies mana.
- “The first,” “the fastest,” “the most decentralized,” or similar comparative claims without current, defensible methodology.
- Statements that conflate native KOIN, wrapped assets, or liquidity across chains.
- Announcements based only on private discussion, rumors, or an unapproved roadmap.
- Attributing an organization’s work to one person without evidence.
- Presenting sponsored material as independent editorial coverage.

## Standard short descriptions

### One sentence

Koinos is a general-purpose blockchain whose mana system helps developers build applications where users do not need to spend a transaction fee for every interaction.

### Short paragraph

Koinos is an open-source, general-purpose blockchain designed around familiar application experiences. Its rechargeable mana resource can be delegated, enabling developers to sponsor blockchain interactions for users, while its modular architecture and on-chain governance allow the protocol to evolve.

Treat these as reviewed starting points. Recheck technical and governance wording against current official sources before using them in a high-impact publication.
