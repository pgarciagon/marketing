# Operations

Operations turns strategy into visible, accountable work without storing secrets or private coordination.

## Core files

- [Action board](action-board.md) — current priorities, owners, next actions, and review dates.

## Status definitions

| Status | Meaning |
| --- | --- |
| Proposed | Worth considering; no commitment or owner yet |
| Researching | Evidence or requirements are being gathered |
| Ready | Brief, owner, evidence, and authority are sufficient to begin |
| Active | Work is underway and has a next action |
| Waiting | A named external response or prerequisite is pending |
| Measuring | Distribution is complete and results are being collected |
| Complete | The defined outcome and verification are recorded |
| Paused | Intentionally stopped with a reason and review condition |
| Cancelled | Closed without execution or completion, with rationale |

## Coordination cadence

A lightweight weekly review should answer:

1. What changed in the outside environment?
2. Which work has no owner or no next action?
3. Which claims or assets need re-verification?
4. What is ready for review or publication approval?
5. What did completed distribution teach us?

Update documents only when state changes. Do not create activity reports that contain no decision, result, blocker, or next action.

## Decision records

Material decisions should be captured in the relevant campaign or strategy document with:

- date;
- decision;
- participants or decision owner;
- evidence considered;
- alternatives rejected;
- review condition.

Do not use repository history as the only explanation for a consequential decision.
